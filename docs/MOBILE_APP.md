# HUB: мобильное приложение и админка

Это адаптивное веб-приложение / Telegram Mini App на Next.js. Основной интерфейс рассчитан на телефон: тёмный фон, оранжевые действия, карточки подписок, нижняя навигация из пяти разделов и боковое меню по предоставленным референсам. На компьютере появляется постоянная боковая панель. Нативных сборок iOS/Android нет.

## Быстрый локальный запуск

Node.js 22+. Из корня этой ветки:

```sh
npm ci
npm --prefix web ci
npm run dev:app:demo
```

Открыть http://localhost:3000. Стенд сам поднимает API на 3001, временную MongoDB и веб. Токен бота и настоящая база не нужны. Первый запуск может скачать MongoDB 8.2.6; бинарник кешируется. Остановить Ctrl+C. Можно изменить API_PORT и WEB_PORT. Данные тестовые и исчезают при остановке.

Верхняя плашка переключает владельца команды и суперадмина. Этот переключатель существует только в development с явно разрешённой локальной авторизацией. В демо есть шесть подписок, команда, устройство, урок, обращение поддержки и оплата на проверке. Telegram-уведомления отправляются только в симулятор. Скачивание реальных чеков и медиа нужно проверять с отдельным тестовым ботом: демо не содержит настоящих Telegram file_id.

Шаги Telegram-мастеров объединены в формы и карточки. Состояния берутся из общей базы. Например, решение админа в Telegram появляется в мобильной версии после обновления данных (опрос раз в 5 секунд). Изменения текста общих справочных экранов и каталога приходят из API. Новая функция бота с новым типом действия потребует API-контракта и интерфейса; существующие данные не дублируются во фронтенде.

## Администраторы

Ещё → Управление HUB. Разделы появляются по действительным правам роли; сервер повторно проверяет каждое действие. Есть пользователи, команды, подписки, оплаты и чеки, поддержка, переписка по оплатам, устройства, заявки, проверки потоков, очередь ProPresenter, потоки, продления и решения по местам, Яндекс 360, темы и уроки, загрузка медиа, рассылки, администраторы, доставка уведомлений и журнал действий.

Формы административных действий строятся по серверной схеме OpenAPI. Связанные команды, продукты и устройства выбираются по названиям; для записи вне загруженной выборки можно ввести ID. Изменение роли, удаление и принятие финансового решения требуют явного подтверждения в интерфейсе. Повторный клик блокируется во время запроса. В списках есть пагинация; в административном обзоре счётчики отражают ограниченную выборку и подписаны соответственно.

Рассылка создаётся как черновик с зафиксированными адресатами, отдельно запускается после подтверждения; можно следить за доставкой и отменить оставшуюся очередь. Медиа загружается через сервер с проверкой размера/типа, затем выбирается в уроке или рассылке. Telegram-токен и внутренний file_id в браузер не выдаются.

## Реальный тестовый бот

Настройка API и переменных — в [WEB_API.md](WEB_API.md) и `web/.env.example`. Веб должен работать по HTTPS, `/api/*` проксируется на API; адрес задаётся через MINI_APP_URL в боте. Боевой вход — подписанный Telegram initData. В обычном браузере без запуска из Telegram доступен только локальный dev-режим. После истечения initData нужно заново открыть Mini App. Автономный офлайн-режим не предусмотрен.

Существующие ограничения бизнес-логики сохранены: нельзя заново купить уже действующую контентную подписку; для ProPresenter используются очередь и кампании продления. Старые кампании с оплатой за команду позволяют сохранить решение о продлении, но веб-оплата устройств требует кампании с device billing. В переписке по оплате поддерживается текст и просмотр существующих вложений; новые файлы отправляются в поддержку.

## Проверки

```sh
npm run build
npm run typecheck:api
npm test
npm run test:api:integration
npm --prefix web run build
npm --prefix web run typecheck
```

CI выполняет эти проверки и установку зависимостей обоих приложений. Интеграционный тест проверяет настоящий HTTP и временную MongoDB, общие сервисы Telegram, права доступа, оплату, подтверждения/отказы, обращения и вложения, заявки, Яндекс 360, уроки и рассылки. Дополнительно проверяются прямые ссылки новой админки и запрет доступа обычному пользователю.

Перед боевой выкладкой нужны проверка индексов из WEB_API.md и проверка настоящих Telegram-файлов на отдельном тестовом боте. Эта работа не меняет сервер. Слияние в main запускает существующий автоматический deployment workflow, поэтому PR оставлен открытым.
