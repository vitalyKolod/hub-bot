# Яндекс 360

Данные хранятся отдельно от команд ProPresenter: поток, участник и заявка на email. Участник связан с существующим `User` через `userId`, когда пользователь появился в боте. Привязка до регистрации происходит только по точному Telegram ID. Если ID неизвестен, администратор вручную вводит его в карточке участника. Совпадение имени, username или email никогда не связывает записи.

Админка: `/admin` → «Управление» → «Потоки Яндекс 360». В списке только потоки, новый поток и заявки. Участников и поиск открывайте из карточки конкретного потока; редактирование потока — через «Настройки потока». Добавление участника идёт по шагам: имя → Telegram ID или «ID неизвестен» → подтверждение. Даты вводятся как `ДД.ММ.ГГГГ` (например `28.09.2026`), `-` очищает дату. Статус потока выбирается кнопками «Активен» / «Неактивен» с галочкой у текущего состояния. Заполнение потока не назначает персональную подписку: в карточке потока нажмите «Добавить участника» и укажите его Telegram ID. После этого участник увидит поток в своём разделе Яндекс 360. Права: `streams.view` для просмотра, `streams.edit` для изменения; действия с заявками требуют `requests.edit`. Конечная дата потока вызывает напоминание администраторам, но не меняет статус участников и адресов. Пароли раздел не хранит и не показывает.

Для отдельной темы в административной группе создайте тему «Яндекс 360», отправьте в ней `/threadid`, внесите полученный номер в `YANDEX360_THREAD_ID`, перезапустите бота. Если переменная не задана, заявки остаются в базе и доступны через админку, но уведомление в тему не отправляется. Индексы MongoDB создаются Mongoose при запуске; проверьте `autoIndex` в рабочей среде.

## Локальный импорт

Ссылка на исходную Google таблицу была недоступна во время разработки. Экспортируйте и проверьте листы вручную, затем создайте JSON массив: одна строка на человека. Обязательные поля: `sourceKey` (стабильный уникальный ключ из выгрузки), `stream` (номер или название потока), `name`. Необязательные: `telegramId` (число), `username`, `emails` (массив адресов), `seats` (целое положительное), `amount` (неотрицательное число), `startsAt`/`endsAt` (`YYYY-MM-DD`), `chatLink`, `capacity`, `adminEmail`. Пустой email выражайте пустым массивом. Объединённые имена, семейные группы, несколько мест и спорные значения разрешайте вручную до применения. Новый email импортируется со статусом «ожидает проверки».

```
npx tsx src/scripts/import-yandex360.ts /path/to/export.json
npx tsx src/scripts/import-yandex360.ts /path/to/export.json --apply
```

Первая команда — обязательный просмотр без подключения к БД. Вторая только создаёт новые записи; совпадение `sourceKey` пропускает, конфликт по Telegram ID останавливает импорт. Скрипт не перезаписывает изменения администратора. Не запускайте `--apply` на рабочей базе до проверки выгрузки. Общие логи и тесты не содержат реальных адресов участников.
